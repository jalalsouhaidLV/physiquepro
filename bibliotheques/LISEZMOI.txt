À quoi sert chaque bibliothèque (modules de sources/build/) :
- jszip : lire le .zip de Google Drive dans Paramètres > Importer (16-import.js).
- jspdf : fabriquer un PDF : bilan d'un élève (21-pro.js), copie annotée par le prof (19-nouveautes.js),
  fiche annotée et travail scanné par l'élève (30-classroom.js).
- pdfjs : lire un PDF pour l'annoter (19-nouveautes.js, 30-classroom.js). Il est ouvert avec
  « isEvalSupported: false » : second verrou contre la faille CVE-2024-4367 (corrigée dans pdf.js 4.2.67),
  en plus de la règle CSP.
- katex (+ mhchem + polices) : éditeur de formules (23-outils-sciences.js).
- html-to-image : image PNG d'une formule (23-outils-sciences.js).

Les adresses utilisées par le site finissent par « ?v=1 » : le service worker (sw.js) garde alors le fichier
dans l'appareil (copie locale d'abord). Le numéro de version est dans le nom du dossier.

Vérifier que rien n'a bougé :   cd bibliotheques && sha256sum -c EMPREINTES.sha256
Essayer les outils :            node sources/tests/test-bibliotheques.js   (depuis la racine du dépôt)

Changer de version (une bibliothèque à la fois) :
1. npm pack <paquet>@<version>, puis comparer l'archive à « npm view <paquet>@<version> dist.integrity » ;
2. copier les fichiers dans un nouveau dossier au nom de la nouvelle version, avec LICENCE.txt ;
3. changer l'adresse dans le module concerné, lancer ./sources/build/build.sh ;
4. supprimer l'ancien dossier, refaire EMPREINTES.sha256, mettre ce fichier à jour ;
5. lancer test-bibliotheques.js, test-site.js et test-telephone.js, puis essayer l'outil sur un vrai fichier.

La bibliothèque qrcode.js (QR code d'un cours) est à la racine du dépôt depuis plus longtemps.
supabase-js et msal-browser restent chargées depuis jsDelivr, avec vérification d'intégrité (SRI), dans index.html.
