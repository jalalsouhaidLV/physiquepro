*Sorti de `sources/FICHE-PHYSIQUEPRO.md` (ancienne section 12) le 26/11/2026, sans modification. Les nouvelles entrées s'ajoutent à la fin. Les règles et l'état actuel sont dans la fiche ; ce fichier ne fait que raconter.*

- **20 octobre 2026** : le fichier du calendrier a été effacé par le bouton « Supprimer les fichiers inutilisés ». Corrigé : les fichiers du dossier `prof/` ne sont plus jamais comptés comme inutilisés, et le calendrier est devenu un lien Google Drive.
- **Ménage du 4 novembre 2026** : anciens doublons supprimés de la racine du dépôt (16 scripts SQL 06 à 22, dossiers `build/`, `site/`, `supabase/` du 18 octobre) — les bonnes versions sont dans `sources/`. Récupérables dans l'historique Git si besoin.
- **Cloche des notifications (11 novembre 2026)** : chaque notification non lue a une coche « Marquer comme lu », et l'ouvrir la marque aussi comme lue. Les notifications lues une à une sont gardées dans `profiles.prefs.lus` (enregistré par `pp_prefs`, donc pareil sur tous les appareils, pas de nouveau script SQL) ; « Tout marquer comme lu » garde `pp_vu` (date `vu_le`). Sur téléphone (≤ 600 px), le menu prend toute la largeur de l'écran : avant, il dépassait à gauche et le texte paraissait coupé.
- **Notifications quand le prof rend une note (11 novembre 2026, script 37)** : (1) **push** : l'élève touche « Activer les notifications sur cet appareil » (Profil > Notifications, module 29-push.js) ; l'abonnement est rangé par `pp_push_abonner` dans `pp_push_abonnements` (aucun droit direct, chacun ne lit que ses appareils). À chaque note rendue (« Rendre » ou « Rendre toutes les notes saisies »), le navigateur du prof appelle la **fonction Supabase `pp-push`** (Edge Function, code dans `sources/supabase/fonctions/pp-push/`, verify_jwt, réservée au prof pour l'envoi), qui envoie la notification Web Push et efface les abonnements périmés ; `sw.js` l'affiche et ouvre le devoir au toucher. Les clés VAPID sont créées par la fonction elle-même la première fois et rangées dans `pp_push_cles` (rôle service seulement) : personne ne les copie. iPhone : iOS 16.4+, site ajouté à l'écran d'accueil et ouvert depuis l'icône ; Android : Chrome suffit. (2) **e-mail** : envoyé depuis l'Outlook du prof par Microsoft Graph (`/me/sendMail`, permission déléguée Mail.Send, élèves en copie cachée, un e-mail par devoir) ; interrupteur « Envoyer aussi un e-mail » dans Profil du prof (préférence `mail_notes`). (3) **messages d'urgence (11/11/2026, ?v=202611111830)** : quand le prof écrit un message d'urgence à un élève (« Écrire à un élève ») ou répond à son message urgent, `pousserUrgent()` (18-urgences.js) appelle aussi `pp-push` : notification sur le téléphone de l'élève, même site fermé, qui ouvre le cours ; le message de confirmation du prof dit si l'élève a activé les notifications. Avant, l'alerte n'apparaissait que site ouvert. Pour que les élèves activent les notifications (choix de Jalal du 11/11, ?v=202611111900) : carte « Sois prévenu sur ton téléphone » sur l'accueil de l'élève tant que ce n'est pas activé sur l'appareil (bouton « Activer les notifications », ou « Installer PhysiquePro » sur iPhone hors écran d'accueil ; « Plus tard » la cache 3 jours), et bouton « Être prévenu sur ce téléphone la prochaine fois » dans la grande alerte d'urgence (`carteNotifsEleve()`, `pushProposable()` dans 31-telephone.js). Android : `new Notification()` y est refusé (on n'entendait que le bip du site ouvert en arrière-plan) ; `notifier()` passe alors par `registration.showNotification()` du service worker, avec la même étiquette (`urg-<id>`, `urgrep-<id>`) que la notification push, pour n'en afficher qu'une. **Panne du 11/11 au soir (corrigée, ?v=202611112010)** : la déconnexion (« Se déconnecter ») fermait la session sur TOUS les appareils (`signOut()` global) ; le navigateur du prof gardait un jeton encore valable pour la base, mais `pp-push` (getUser) le refusait (401) : aucune notification ne partait. Corrigé : déconnexion de cet appareil seulement (`signOut({ scope: "local" })`), `pp-push` version 2 qui lit le jeton déjà vérifié par la passerelle si la session n'existe plus, 2e essai après renouvellement (`invoquerPush()`, 29-push.js), et le message du prof dit « notification non envoyée » en cas d'échec. **Message urgent d'un élève → téléphone du prof (12/11/2026, script 46, pp-push version 3, ?v=202611121000)** : avant, rien n'envoyait de notification au prof (alerte seulement site ouvert) et le prof n'avait aucun bouton pour abonner son téléphone. Maintenant `envoyerUrgent()` (18-urgences.js) appelle `pp-push` avec `{ action: "urgent", id }` ; la fonction relit le message dans la base (il doit être à l'élève qui appelle, récent de moins de 10 min, jamais signalé : table `pp_push_urgents`), puis prévient tous les appareils abonnés des comptes `role = prof` (titre « ⚠ Message urgent · nom », ouvre #/urgences). Le prof abonne chaque appareil par la carte « Sois prévenu… » de l'accueil, la barre « Activer » de la Messagerie d'urgence, ou Profil > Notifications > « Sur ce téléphone ou cet ordinateur » (`pushProposable()`, `carteNotifsEleve()`, `blocPush()` valent maintenant aussi pour le prof). `majEtatPush()` n'affiche « Activées sur cet appareil » que si l'abonnement du navigateur est rangé au nom du compte connecté (?v=202611121005) : un téléphone abonné avec un compte élève de test montrait « Activées » au prof sans rien lui envoyer ; « Activer » réattribue l'abonnement au compte connecté (pp_push_abonner). **Message d'urgence à plusieurs élèves (12/11/2026, ?v=202611121130)** : la fenêtre du prof (« Écrire aux élèves », `modalUrgProf()` dans 18-urgences.js) a une case « Toute la classe » et la liste des élèves du cours (déjà connectés au site) à cocher ; cocher la case coche tout, décocher un élève la décoche, sans effacer le message (`cocherUrg()`). `envoyerUrgProf()` enregistre une ligne `messages_urgents` par élève (un seul insert, permis par la règle `mu_prof`, aucun SQL nouveau) puis appelle `pp-push` une fois par élève avec l'étiquette de son message (`urg-<id>`), pour garder une seule notification par téléphone ; la confirmation donne le nombre d'élèves prévenus sur leur téléphone. Testé par test-site.js (bloc « message d'urgence »). **Notifications des messages urgents d'élèves fiabilisées (12/11/2026 au soir, script 48, fonction `pp-urgent`, ?v=202611121830)** : Jalal recevait la notification « parfois oui, parfois non ». Cause prouvée par les journaux : les 6 messages d'élèves du 12/11 venus de **physiquepro.netlify.app** n'ont déclenché aucun appel (la copie Netlify, publiée le matin, datait d'avant `invoquerPush({action:"urgent"})`) ; tous ceux venus de github.io ont sonné. Plus généralement, faire partir la notification du téléphone de l'élève la perdait aussi en cas d'ancienne version en cache, de réseau coupé ou d'appli fermée tout de suite. **Maintenant c'est la base qui l'envoie** : le déclencheur `pp_urgent_signaler` (AFTER INSERT sur `messages_urgents`, élève seulement, pg_net) appelle la fonction Supabase **`pp-urgent`** (code dans `sources/supabase/fonctions/pp-urgent/`, verify_jwt = false, protégée comme pp-rappels par l'en-tête `x-pp-cle` = `pp_rappels_cle`) ; elle traite tous les messages d'élèves de moins de 15 min pas encore remis (rien n'est pris dans la demande), les envoie à tous les appareils des comptes prof (notification « insistante » : reste affichée jusqu'au toucher, vibre fort, `sw.js`), et range le résultat dans `pp_push_urgents` (`termine`, `essais`, `envoyes`, `appareils`, `detail`). Filet : la tâche pg_cron **`pp-urgent-filet`** (chaque minute, aucun appel si tout est remis) relance tant qu'aucun appareil n'a reçu, 6 essais au plus. `envoyerUrgent()` n'appelle plus pp-push (l'action « urgent » de pp-push v3 reste pour les vieilles copies du site, sans danger : un seul envoi par message grâce à la clé de pp_push_urgents). Dans la Messagerie d'urgence, chaque message reçu affiche « Notification remise à N appareils à HH:MM » ou « non remise » / « aucun de tes appareils n'est abonné » (`suiviPush()`, 18-urgences.js ; pp_push_urgents lisible par le prof seulement). **Abonnement entretenu tout seul** (`entretenirPush()`, 29-push.js) : à chaque ouverture du site, si les notifications sont autorisées et que l'appareil a déjà été activé avec ce compte (repère `pp-push-voulu-<id>` dans le navigateur) ou que c'est le prof, l'abonnement perdu ou changé par le navigateur est refait et rangé au nom du compte connecté, sans question. Vérifié le 12/11 à 18 h 08 UTC : message d'essai n° 125 → notification remise aux 2 appareils du prof (Android + ordinateur) par le serveur. **Diagnostic en cas de doute** : `select * from pp_push_urgents order by message_id desc limit 10` (envoyes/appareils/detail), `select * from net._http_response order by id desc limit 5` (réponses de pp-urgent), et `query_logs` function_edge_logs. Ce qui reste hors du site : le son dépend des réglages du téléphone (Android : Paramètres > Applications > Chrome > Notifications > le site PhysiquePro, son activé et « Prioritaire » ; mode Ne pas déranger ; économiseur de batterie qui retarde Chrome ; iPhone : site installé sur l'écran d'accueil, notifications de PhysiquePro autorisées avec Sons). **Une seule alerte par message (12/11/2026, 21 h Beyrouth, ?v=202611122115)** : Jalal recevait 3 alertes pour un message d'élève : la notification push, puis en ouvrant l'appli la même notification refaite par la page (`notifier()` → `showNotification` avec la même étiquette et `renotify`), plus le bip et la grande alerte. Le serveur, lui, n'envoie bien qu'une fois (vérifié : messages 128 et 129, 1 essai, 2 appareils). Règle dans `notifier()` (18-urgences.js, `pushIci()`) : appareil abonné aux notifications push au nom du compte → la page ne sonne pas et ne refait pas de notification (prof : seule la pastille rouge se met à jour ; élève : la grande alerte reste, en silence, pour lire le message) ; appareil non abonné : site au premier plan → grande alerte + bip, site en arrière-plan → une notification du navigateur et rien d'autre. `sw.js` : une notification déjà affichée pour le même message ne sonne pas une 2e fois (`getNotifications({tag})`). Chaque appareil abonné du prof (téléphone, ordinateur) reçoit sa notification : pour n'en avoir que sur le téléphone, « Désactiver sur cet appareil » dans Profil > Notifications de l'ordinateur. Test automatique dans test-site.js (bloc « une seule alerte », 4 situations, prof et élève ; accès `window.__ppTest` présent seulement en test).
